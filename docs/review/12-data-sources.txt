Import your own wearable data

Imported data uses its own detector settings. The on-board model is set for the full sensor set and, given only a watch's overnight heart rate, alerts far less often than its budget and flags fewer episodes. So an import runs on a heart-rate-only model whose thresholds were calibrated on 251 real people; its expected performance is the "heart rate alone" row on the Validation screen (about one false notice a month), measured mostly on Fitbit wearers; other watches did worse in the real data, in a small sample, and many Apple Watch recordings were too sparse to use. Activity and sleep in the file are shown but not used by the detector; blood pressure and blood sugar in the file are checked against the same fixed lines as typed readings. One more difference: the model was calibrated on resting heart rate computed from raw night-time samples, while an import gives the watch maker's own daily resting heart rate, which is smoothed differently. Tried on Fitbit's own daily values for 63 people in another dataset, it gave about one alert a month at the notice tier, as budgeted, and about twice its budget at the alert tier.

Read in this browser only; the file is never uploaded. Keel then learns your baseline from it and shows the same Today and Trends screens for you. Supported: a CSV with a date column and any of rhr, hrv, spo2, temp (a wrist sensor), temperature (a thermometer), sleep_h, ex_min, mood, fluid, mass, sbp, dbp, glucose; dates as YYYY-MM-DD, or day/month/year or month/day/year when the file shows which; Fitbit export JSON (resting heart rate, sleep); Apple Health export.xml. Several readings on one day are averaged, except blood pressure, blood sugar and oxygen, where the most extreme reading of the day is kept. Blood sugar in mmol/L is converted to mg/dL when most of the file is under 35; otherwise a value under 35 is kept, treated as dangerously low and listed so you can check it.
