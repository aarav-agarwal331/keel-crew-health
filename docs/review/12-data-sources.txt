Import your own wearable data

Imported data uses its own detector settings. The on-board model is set for the full sensor set and, given only a watch's overnight heart rate, would almost never alert. So an import runs on a heart-rate-only model whose thresholds were calibrated on 251 real people; its expected performance is the "heart rate alone" row on the Validation screen (about one false notice a month), measured mostly on Fitbit wearers; other watches did much worse in the real data, and many Apple Watch recordings were too sparse to use. Activity, sleep and the other readings in the file are shown but not used for alerts. One more difference: the model was calibrated on resting heart rate computed from raw night-time samples, while an import gives the watch maker's own daily resting heart rate, which is smoothed differently, so its false-alert rate on your data may differ.

Read in this browser only; the file is never uploaded. Keel then learns your baseline from it and shows the same Today and Trends screens for you. Supported: a CSV with a date column and any of rhr, hrv, spo2, temp, sleep_h, ex_min, mood, fluid, mass, sbp, glucose; Fitbit export JSON (resting heart rate, sleep); Apple Health export.xml.
